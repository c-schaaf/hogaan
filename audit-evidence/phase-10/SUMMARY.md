## Re-running

Every Phase 10 row is regenerated by re-running its source test or
script. To rebuild the entire audit evidence directory:

```bash
# Re-run the deterministic Phase 10 tests:
pnpm test tests/phase-10

# Re-run the latency harness (gated on ops approval for live LLM cost):
pnpm exec tsx scripts/profile-latency.ts --concurrency 20

# Re-run alpha-cohort provisioning (live, requires real phone list file):
pnpm exec tsx scripts/provision-alpha-cohort.ts \
    --sponsor "Test Sponsor" \
    --cohort "Phase A Alpha" \
    --phones path/to/phones.txt
```

Output files land in `audit-evidence/phase-10/`. Each filename is
`<YYYY-MM-DD>-<test-id-slug>.json`.

## Existing-test tagging (from prior batches)

The 252 existing tests at the start of Phase 10 already cover many
controls (see the carry-forward rows above). A formal retroactive
tagging pass — adding `recordEvidence()` calls to every existing
test — is **not** done in this batch. The baseline tests still emit
their pass/fail signals to CI; the audit binder just doesn't have
per-test JSON rows for them.

This is acceptable for the Phase A audit because the controls those
tests prove ARE represented in carry-forward evidence rows under
T1/T2/T3 above. A future batch can mechanically tag each test file
with a `recordEvidence({...})` call in `afterEach` if the audit
lead requires per-test granularity.
